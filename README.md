# 节点是什么：格式、延迟与倍率

节点在本文指代理配置所描述的服务器出口，clash节点、vpn节点、v2ray节点不能只按叫法互换输入。延迟对应测试配置与结果的不同问题，倍率则是口语计费称呼；这里只解释配置对象和字段边界，不提供资源或品牌。

## 节点名称不是协议定义或资源清单

客户端显示的名称与服务器连接参数属于不同内容。名称能用于阅读列表，却不能单独确认对应什么协议、输入格式或运营主体。本文没有实际节点资料，不会根据一个名字给它填服务器地址、认证信息或可用状态。

协议文档提供的是类型与字段，例如 mihomo 的 SOCKS 页使用 `socks5`，Shadowsocks 页使用 `ss`，Trojan 页使用 `trojan`。这些类型值有各自语境，不是把任意中文节点名改成某个词就可以替换。字段结构与显示名称仍需分开。

HTTP CONNECT 规范又描述代理向目标建立隧道，请求目标包含主机和端口。它确认的是协议交互，不是一份公开服务器清单。本文不从规范示例推出存在可供使用的远端资源，也不把目标地址视为任何商家的声明。

SOCKS5 的规范包含 TCP、UDP 框架及相关命令，能够帮助区分协议概念。它不负责定义“VPN 节点”这类口语标签，也没有为本文确认某个资源运营者。协议名字出现在配置里，不代表身份与服务条款都已明确。

因此，节点这一主题先保持在配置所描述的出口，不把名称、协议与资源交付合成同一项目。本文所用概念资料分别以 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110)、[RFC 1928](https://www.rfc-editor.org/rfc/rfc1928) 表示，不附任何可连接地址。

## proxies 与代理集合处于不同组织层

mihomo 的出站协议页围绕代理条目组织类型和字段。`proxies` 这个配置对象与 `proxy-providers` 的集合来源不是同一项，不能只因界面最终都显示列表就把两者交换。本文只根据文档已经列出的内容解释层次，不给完整配置模板。

代理集合的 `type` 可写 http、file、inline。http 对应地址取得，file 指本地文件，inline 则通过 payload 直接写列表；来源方式不同，不能从其中一个存在就推断资源附带在客户端里。配置的取得方式与资源经营属于不同问题。

文档要求 http 类型有 url。payload 在 inline 时生效，另可在 http、file 解析失败时作为备用列表；这些是页面明确给出的条件，不能删去适用范围后称 payload 永远覆盖所有来源。本文也不编备用列表的真实内容。

有地址不等于已经拉取成功，有本地文件不等于已经完成解析。这里没有执行请求或解析，所以不使用成功记录来描述示例字段。目录中列出的配置能力，也不会替实际资料生成运行结果。

集合文档的阅读入口是 [mihomo 官方文档站](https://wiki.metacubex.one/)。它与客户端界面里“导入订阅”的名称相关，但不是某款应用按钮的逐字说明；没有应用界面资料时，不能把集合字段改写成点击教程。

## 内容形式与来源类型不能放在同一栏

代理集合文件内容页列 yaml、uri、base64 三种形式。这一组讲文件内容怎样表示，而 http、file、inline 那组讲集合从哪里取得或怎样放进配置。两种分类回答的问题不同，不能合并成六种可任意交换的格式。

该页特别要求，不把 YAML、URI、BASE64 混写在同一个文件。URI 和 BASE64 形式不需要 `proxies:` 字段，这也是页面已有的范围说明。本文不把这一条件扩为其他项目完整配置语法，也不从表现形式推断资源是否可信。

URI 的页面示例出现 ss、vmess 的前缀，但未给出全部协议前缀支持清单。这里不能借示例补成任何协议链接都可解析，更不能因为另有协议配置页就宣布对应 URI 一定支持。两份页面需保留不同问题。

同样，某个客户端名称带 V2Ray 或 Clash，不能据此确认实际收到哪种内容。需要以输入说明和内容本身核对，本文没有取得实际文件，所以不判断特定资源的格式。名称并不是解析结果。

| 分类问题 | 文档列出的项目 | 适用范围 |
| --- | --- | --- |
| 来源类型 | http、file、inline | 代理集合取得或内置方式 |
| 文件内容 | yaml、uri、base64 | 对应内容页的形式 |
| 代理类型 | 各协议页的 type 值 | 单个条目的配置参考 |

表中没有资源数量，也不构成客户端支持矩阵。本文只说明三个分类维度，不为未列出的组合填兼容结论。

## health-check 的字段与延迟结果分开

代理集合文档列有 health-check，下面包括 enable、url、interval、timeout、lazy、expected-status。这里能确认的是这些字段名出现在配置参考里，不能只凭名称把未取得的默认值和单位补齐。本文不提供真实公共探测地址。

若记录“健康检查配置是什么”，可把字段名和来源对应；若记录“延迟是多少”，则需要实际测量。两类记录不会因在同一界面显示而互相替代。本文没有测试任何出口，也没有给节点设置分数。

文档还列 provider 自身的 interval，并明确其单位是秒。这个更新间隔与 health-check 下的同名字段不是同一层对象，不能把一处说明未经核对地贴到另一层。名称相同不代表本文已确认全部含义相同。

配置存在也不说明检查成功，检查入口存在也不说明资源身份明确。这里不依据单个状态判断远端服务的经营情况，更没有一份把错误色彩对应到原因的表。页面字段与实际错误记录之间仍需独立证据。

本节因此只列字段边界，不示范测试资源、不列延迟数字、不写配置保证怎样改善结果。所谓延迟在这里是需要另有结果记录的问题，没有被一个 health-check 标题自动回答。

## 更新、过滤与覆写是不同配置项目

集合资料中还有 path、proxy、size-limit、header 等字段。path 与保存位置有关，proxy 对应经指定代理取得资料，header 对应自定义请求头；未取得的字段操作细节，本文不靠名字补一份完整教程。这里只保留文档明确给出的项目关系。

filter、exclude-filter 与 exclude-type 在页面中分别出现。文档对 exclude-type 说明不是正则表达式，类型之间用竖线分隔；它与名称过滤并非同一写法。本文不根据某个条目名字推断应该保留或排除哪些类型。

override 另有增加前后缀、名称正则替换以及其他参数。它描述集合条目的覆写入口，不代表任何外部文件的全部字段都被接受。名称变动与服务器或凭据变动也不能在这里画等号。

来源、内容、过滤和覆写可出现在同一组配置资料中，却需要分别记录。改变列表呈现的功能不直接回答可用性，改变取得方式也不证明资源交付发生变化。本文没有针对实际集合执行任何修改。

Verge 的内核资料还指出 path 受安全目录范围限制。这个条件属于目标内核配置，不是任意客户端可写到任何目录的承诺。没有取得某应用自己的路径规则时，不能将内核字段当作完整界面行为。

## 倍率只保留为口语计费问题

“倍率”在这里是圈内的口语说法，没有统一技术定义。所用代理协议与配置文档没有为本文提供一份具体服务的扣费公式，因此不写某个倍率怎样扣量，也不提供实际套餐示例。这个词不能用来替代协议或服务器类型。

它与 health-check 的字段也不在同一问题里。配置检查如何设置属于软件资料，费用怎样计则需要服务条款；没有服务原文，就不能把客户端显示的某个数字直接解释为扣费规则。本文没有商家资料可用于完成这段对应。

同样，延迟、数据额度、计费周期与倍率不是相互换算的统一单位。本文没有测量或结算数据，不能在这些栏目间计算出成本或使用时长。术语解释仅保留对象差别，不补运营惯例。

节点名字若带某个费用相关标记，也不能由名称本身确认条款。需要实际说明才能解释，本文不收集或展示这种资源。没有具体记录时，只能说这里没有对应依据，不能自行编出含义。

这一边界使本文不需要服务品牌、购买入口或资源名单。倍率主题到阅读具体条款为止，配置主题到官方字段为止；二者都没有被用来给出口好坏定性。

## 不用内核目录给所有客户端背书

sing-box 的文档同样分入站、出站与 Endpoint，入口用 [sing-box 官方文档](https://sing-box.sagernet.org/) 表示。目录里与 mihomo 相同的协议名字，并不能确认两者整份配置互通。本文不在不同项目之间交换字段、默认值或来源类型。

mihomo 某协议页存在，只说明有对应参考。最低版本、URI 支持全貌及每款图形应用的呈现能力仍可能需要另有资料，不能将一张目录扩为全部承诺。本文没有按协议数量判断产品能力。

节点概念、来源集合、内容形式、检查字段与计费术语至此分别有各自位置。本文没有提供服务、没有解析真实输入，也没有对任何资源执行测试。可确认的是资料结构，不是某个出口已经可用。

后续若有真实配置需要记录，也必须保留其来源与实际结果，不能只把本文占据的栏目填满就宣称核对完成。空缺是一项资料状态，不代表自动通过，也不代表自动否定。本文不补出任何未经取得的运行事实。

## FAQ

### 节点名字能确定协议吗？

名称与协议类型是不同对象。本文没有据显示名称给真实资源填协议或身份。

### http 与 base64 是同一组分类吗？

前者可用于来源类型，后者属于内容形式。它们不能合成一组可任意互换的选项。

### URI 示例有两个前缀，就支持所有前缀吗？

页面没有提供完整清单。示例不能扩写成全部协议链接均可解析。

### 配了 health-check 就有延迟结论吗？

配置与实际测量是不同记录。本文没有执行检查，不输出节点结果。

### 两层 interval 能直接用同一解释吗？

它们属于不同层的对象。本文只在明确给出单位的地方采用相应说明。

### 倍率有统一技术公式吗？

本文将其视为口语计费称呼。没有具体服务条款，不补扣费公式。

### 过滤名称能确认资源经营情况吗？

过滤字段处理配置列表。它不提供经营主体、服务状态或费用的确认依据。

### 本页有节点可以使用吗？

没有，这里只讲配置概念与字段。本文不交付地址、凭据或资源清单。
